# Review a new book import

1. Record the author, edition, intended use and applicable source rights. Preserve original bytes and notices. Public accessibility alone does not establish permission to redistribute.
2. Hash the source and create an explicit profile. Inspect representative layouts, indexes, tables, footnotes, split recipes and chapter transitions.
3. Extract into a fresh candidate directory. Preserve original blocks/cells, normalizations, held records and supporting prose; do not discard inconvenient evidence.
4. Compare against the source. Check fractions, quantities, order, missing steps, title boundaries and continuation pages. Record source corrections separately from interpretations. Keep printed page labels distinct from file-page indices.
5. Review related preparations and alternatives. A link or ingredient mention alone does not establish a required dependency. Bind accepted decisions to current source hashes and recipe revisions. Pending reports from the importers are work queues, not acceptance receipts.
6. Validate the candidate schema and reader behavior. For a v2 migration, emit the canonical contracts in `library_v2/schemas/content.schema.json`, run compiler validation and compare complete reads against the accepted canonical input. EPUB/PDF-to-v2 promotion is an explicit integration task.
7. Evaluate retrieval and complete reads with source-grounded questions. Distinguish extraction fidelity, search relevance, assistant behavior and personal cooking feedback; a passing test in one area does not establish the others.
8. Keep the previous accepted build available. Publish only code and content you intend and are permitted to share. No import command in this toolkit activates a hosted service.

See [toolkit commands and examples](toolkit.md) and [public HTML profile guidance](importing.md).
